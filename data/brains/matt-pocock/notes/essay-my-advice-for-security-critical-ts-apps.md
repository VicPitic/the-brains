## Branded types as the security tool for TypeScript apps

- When Matt is asked how to approach a security-critical TypeScript app, his advice is to "use the crap out of branded types".
- He points to a Twitter thread he wrote on branded types (posted February 2023) as the longer explanation.
- Branded types are the tool he reaches for when the cost of mixing up values is high.

## Why TypeScript wizardry matters to teams

- TypeScript is now the most popular language on GitHub. It overtook JavaScript in PRs per week.
- Matt says TypeScript can feel very different from JavaScript: strange syntax, arcane inference rules, generics.
- Because of that, it is "extremely tempting to just ignore the errors and slap on an 'any'".
- He notes that most TypeScript application code is written under severe time constraints. In his words, apps get built on "blood, sweat and 'as any'".

## Turning any into safe types

- As TypeScript takes more market share, he expects TypeScript "wizards" to be in higher demand.
- His core claim: "Having the knowledge to transform any's into safe types will save your team bugs."
- This is a way to make your skills more valuable. It is not only about cleaning up legacy code.

## Type wizardry as a DX multiplier

- Beyond cleanup, advanced TypeScript knowledge lets you build DX improvements that accelerate a team.
- Examples he gives of abstractions that need this knowledge:
  - A custom form abstraction.
  - A type-safe REST API endpoint creator.
  - A flexible Table component.
- His career argument: "The more you can enable your teammates to develop faster, the faster you'll rise up the ladder."
- He describes this as satisfying, engrossing work: designing and implementing APIs that help other developers code faster.
